        Guide

        What you are watching

        An attacker agent and a defender agent take turns against an API that keeps growing. Each round the API changes, the attacker tries every collection as the wrong user, the defender switches on a fix and proves it, and a fresh attacker run checks the fixes held.

        The loop

        Drift reverts some verified fixes at the start of a round, like a deploy that rolls back part of the configuration. The loop must notice each one as a regression and fix it again.

        Reading the lamps

        Each lamp is one collection (for VAmPI, one attack check). Waiting: not tried yet. Probing: the attacker is trying it now. Breached (red, hatched, "!"): one user reached another user's data. Fixed by defender (green, shield): a verified fix is in effect. Secure (green outline): it was never vulnerable. Unclear (amber, dashed, "?"): the check could not run cleanly, so it is not safe. A "new" notch marks a collection added this round; "reverted" marks a fix drift switched off.

        Reading the scoreboard

        Found: breaches the attacker confirmed this round. Fixed: of those, how many have a verified fix that still held on the fresh run. New exposure: collections that were vulnerable the first time they appeared. Regressions: collections that were secure last round and breached now. Fix rate counts repairs, so a regression fixed again counts twice. Real users OK: two legitimate-use checks per collection after the fixes.

        Targets

        The 8 vulnerability templates

        Every collection is one of these shapes. All ask the same thing: can one user reach a resource that is not theirs?

        B1 to B7 map to OWASP API1:2023 Broken Object Level Authorization; V1 maps to API5:2023 Broken Function Level Authorization.

        LLM-sampled checks

        Every collection is always checked with plain HTTP requests. Setting LLM-sampled checks above 0 also sends that many random collections to your local Ollama model, which decides and sends the request itself. It is graded from the real responses, never from the model's say-so. Results appear in Findings tagged "LLM".

        Lab controls

        Max collections: the lab grows to this many, then stops (0 means no limit). Grow to limit creates collections now. Vulnerability probability: odds each new scenario is left vulnerable. Auto-grow interval: add one every N seconds (0 means manual only). Paused stops the timer. Reset to 0 clears every collection and switches off the defender's applied fixes, so the next run starts clean. The loop pauses timer growth while it runs and grows the lab at each round boundary.

        Timing

        Deterministic checks finish in about a second per round. A full VAmPI run with the LLM took about 218 s on an 8 GB machine; pause or reset a large lab before LLM runs. Phase pacing slows the loop so the audience can follow it and is not counted in phase durations.
